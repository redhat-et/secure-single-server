# Scenarios

These scenarios begin after a reviewed deployment is already running. Each one
shows a specific control or workflow, names its prerequisites, and states the
evidence it does not claim.

| Scenario | What it shows | Start here |
| --- | --- | --- |
| [Praxis token quotas](praxis-quotas/README.md) | Inspect providers, preview, apply, and verify a shared rolling-day model-token allowance | [Praxis quota scenario](praxis-quotas/README.md) |
| [Streamlit before and after OpenShell](streamlit-security/README.md) | Credential-free managed inference and filesystem confinement in one short demo | [Streamlit walkthrough](streamlit-security/README.md) |
| [OpenCode PR-candidate queue](opencode-pr-queue/README.md) | Selected GitHub issues or prompts become reviewable patch bundles without GitHub write access | [PR queue walkthrough](opencode-pr-queue/README.md) |
| [Review as a service](../development/review-service.md) | Delegated pull-request review in a restricted sandbox that can read public repositories but cannot push or comment | [Review service guide](../development/review-service.md) |

Use these scenarios to see the boundary in practice. Treat a successful demo as
a workflow result, not a substitute for the deployment's separate qualification
tests.
